# Model comparison — Opus 4.8 plan vs Fable 5 plan

> **Compared:** `plan/growth/2026-06-tts-action-plan.md` (Opus 4.8, 2026-06-03, updated through 06-05)
> vs `plan/growth/2026-06-fable5/2026-06-tts-action-plan-fable5.md` (Fable 5, 2026-06-10).
> **Judge:** Fable 5 — ⚠️ **I am grading my own work.** I've tried to be adversarial toward my own
> plan and flag every advantage I had. Discount my verdict accordingly; the dimension scores are
> arguably more useful than the bottom line.

## ⚠️ Three asymmetries that make this NOT a clean model test

1. **Information advantage (big):** Fable 5 re-pulled live data on June 10 — it *knows* the wp.org
   listing reopened and that revenue stayed dead afterward. Opus planned on June 3 under uncertainty
   and handled it well (the R1–R10 reopen-trigger design is exactly how to plan around an unknown).
2. **Second-mover advantage:** Fable 5 read Opus's plan before writing its own. Some sharpness is
   editing, not original insight. A true bake-off would have given Fable 5 only `baseline-data.md`.
3. **Different jobs:** the Opus file has become a *living tracker* (7 status updates, DONE logs,
   session history). The Fable 5 file is a *fresh strategy*. Comparing a used tool to a new one
   flatters the new one.

## Bottom line

**Keep both, with distinct roles — but if forced to pick ONE forward-looking plan, pick the Fable 5
file.** Reasoning:

- The Opus plan's central scenario (closed listing, reopen pending) is **resolved** — a plan organized
  around that uncertainty is structurally out of date no matter its quality.
- The Fable 5 plan is current, half the scope (matching demonstrated execution capacity), fixes two
  real analytical errors (MRR/cash conflation; renewal leak unaddressed), and explicitly decides the
  kill list instead of letting low-value items linger as TODO guilt.
- **However:** the Opus file must NOT be deleted. It holds (a) the execution log of everything done
  June 3–5 (audit trail), and (b) the artifact index + R-action playbook for any *future* closure.
  Archive it as the historical record; run day-to-day from the Fable 5 file.

**Honest model-quality read (asymmetries acknowledged):** on the same raw data, Opus 4.8 produced a
more *comprehensive* plan with better supporting assets; Fable 5 produced a more *decisive* one with
one materially better piece of analysis (renewal economics) and cleaner financial logic. Neither
output is dominated. If you want a clean experiment some day: give each model only
`baseline-data.md` in a fresh session with no prior plan visible, and compare blind.
