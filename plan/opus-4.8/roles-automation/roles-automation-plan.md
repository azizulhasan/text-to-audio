# Roles Automation Plan — AtlasAiDev (solo founder)

> Goal: one person runs ~14 roles. Reduce time/mental load per role so routine work runs
> with less attention, freeing time for the highest-value work: **core product engineering + direction.**
>
> Default rule for every task: **"Can AI draft this first?"** If yes → hand it off, then review.
> Only build from scratch yourself when it's architecture, a founder decision, or hitting **send/publish/ship**.

---

## The 4 buckets

### 🟢 Automate — runs without you (set up once, runs on schedule/trigger)
- **Releases / DevOps** — git-flow + build/release script (mostly done). Add a pre-release **smoke-test checklist** as a gate.
- **QA regression** — rule: *every fixed bug earns one test.* Grows exactly where you get hurt; catches recurring free/Pro breakage.
- **Reminders & sequences** — review-reply reminders, email sequences, milestone notices (drafts already in `plan/`) → put on a schedule.
- **Analytics / growth reports** — a scheduled agent pulls numbers and hands you a summary.

### 🔵 Delegate to AI — I draft, you review (biggest time win)
- **Bug fixing** — you describe the bug; I investigate + propose fix; you verify.
- **SEO / content / blog drafts / listings / schema / keyword work** — near-fully AI-drivable.
- **Technical writing** — docs, setup guides, playbooks.
- **Outreach + review-reply drafting** — I write, you send (**sending stays yours**).
- **Compliance audits** — I flag wp.org / GDPR issues; you decide.

### 🟡 Templatize — make repeatable = fast
- **Free ↔ Pro CONTRACT** (in progress) — kills #1 recurring bug class.
- **Templates:** ticket, release checklist, review-reply, test-case.
- **Reusable setup-wizard blueprint** across products.

### 🔴 Human-only — must stay you
- **Founder direction** — what to build, pricing, which product wins your time.
- **Architecture decisions** — free/Pro boundary, big refactors. *AI drafts, you own the call.*
- **Final send/publish/ship** — releases, emails, public posts. The button is always yours.
- **Customer relationships** — human judgment in a review reply or support answer.
